# Guilds and status-screen social actions — 2026-11-21

ZERO only: https://charidungeon.com/.

Guild affiliation is per character, one guild at a time, maximum 30 members. The left PC menu and mobile navigation open the guild panel. Unaffiliated characters can create a named guild or apply by exact guild name. The panel contains the description, member list/online indicators, personal invitations, incoming join requests for masters, cancellation/decline/approval controls, and leave/transfer/kick controls. Masters must transfer before leaving a populated guild; a solo master's confirmed leave disbands it. No guild chat/shared storage is included in this change.

Right-click a nearby player to open the existing equipment/status window. It now shows their guild and supports exact-character friend requests, incoming friend approval, leader-issued guild invitations, joining the inspected player's guild, and accepting a matching incoming guild request/invitation. Same-account, already-friends, pending, same-guild and other-guild states change/disable the relevant controls. Friendships remain account-wide. Exact character IDs avoid ambiguity when character display names are duplicated. Name-based friend requests with multiple matching characters ask the player to use the status screen.

Migration 202611210001 adds private RLS-enabled guild/member/request tables and private serialization helpers, wrapping the previously validated world RPC. Guild mutations derive the caller character from auth.uid plus active presence, enforce master/recipient authority, reject occupied/full membership, and use the existing mutation lock ordering. One membership per character is a primary-key constraint. Names are case-insensitively unique; requests expire after 7 days and are capped at 5 per character / 100 per guild. Login IDs/emails and unrelated guild rosters/requests are never returned. Previous world wrapper and helper/table access remain revoked for direct authenticated/anonymous calls. Character items, gold, dungeon progression and super flags are untouched.

Guild mutations and friend approval also work inside dungeon rooms; the underlying polling response preserves the current room state. The ongoing realtime encounter clock is unchanged. Input drafts survive polling, guild views avoid HP-driven rerenders, and social buttons are guarded while a request is pending. Member transfer/kick/leave require a second click.

Validation: build; test:guilds (full workflow, ownership/capacity/expiry, character separation, duplicate-name friendships, dungeon inspection/approval, private table/helper ACLs); responsiveness, exploration/adventure and equipment regressions.
